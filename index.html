3-Tier WebGIS & Automated Mining Rights Overlap Detection Portal

Designed and deployed an end-to-end spatial database system that automates the identification and resolution of overlapping mineral title applications under the Mines and Minerals Act. The architecture integrates spatial topology rules, SQL database triggers, and a lightweight web front-end.

Database Engine PostgreSQL / PostGIS
Spatial API / Auth Supabase BaaS

System Workflow Logic
  • Polygon Ingestion: Applicant uploads geo-referenced mining claim polygon.
  • PostGIS Trigger: Executes ST_Overlaps & ST_Intersection against active concessions.
  • Conflict Area Output: Computes exact encroached area ($m^2$) and flags cadastral boundary violations.

Spatial SQL 
CREATE OR REPLACE FUNCTION check_mining_claim_overlap()
RETURNS TRIGGER AS $$
DECLARE
    v_conflict_count INTEGER;
    v_overlap_area   NUMERIC;
BEGIN
    -- 1. Reproject incoming geometry to national grid (UTM Zone 36S / EPSG:32736)
    NEW.geom := ST_Transform(NEW.geom, 32736);

    -- 2. Detect topological intersections against active concessions
    SELECT COUNT(*), COALESCE(SUM(ST_Area(ST_Intersection(c.geom, NEW.geom))), 0)
    INTO v_conflict_count, v_overlap_area
    FROM active_mining_concessions c
    WHERE ST_Overlaps(c.geom, NEW.geom) 
      AND c.claim_id != NEW.claim_id;

    -- 3. Raise conflict exception if spatial encroachment exceeds 0 sq meters
    IF v_conflict_count > 0 THEN
        RAISE EXCEPTION 'Cadastral Violation: Claim % encroaches % sq.m over existing title.', 
            NEW.claim_code, ROUND(v_overlap_area, 2);
    END IF;

    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
